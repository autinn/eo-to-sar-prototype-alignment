# Confounds in the published control experiment

A note on the experimental design of arXiv 2609.07753, based on reading the
authors' released code in `src/`. Nothing here disputes the reported numbers;
the point is what can be concluded from them.

## Summary

The paper's control experiment is intended to answer one question: do the gains
from prototype alignment come from optical structure in the prototypes, or from
the geometry of having well-separated alignment targets at all? It answers this
by swapping real optical class means for a simplex equiangular tight frame
carrying no optical information.

That is the right control to run. But the two conditions differ in **three**
respects simultaneously, not one, so the 4.0 pp gap between them cannot be
attributed to prototype type alone.

## The three differences

Comparing `src/train_eo_prototype_alignment.py` against
`src/train_synthetic_prototype_alignment.py`:

| | EO prototype | Synthetic prototype |
|---|---|---|
| Prototype construction | class means of real EO features | simplex ETF, no optical content |
| `LEARNING_RATE` | `8e-6` | `4e-6` |
| `SEEDS` | `[10, 40, 41, 42, 43]` | `[30, 42, 123, 777, 2025]` |

Everything else is identical. The training loops are byte-for-byte the same
except for a single identifier: `eo_prototypes[labels]` becomes
`synthetic_prototypes[labels]`. LoRA rank, alpha, dropout, target modules, batch
size, epoch budget, weight decay, early-stopping patience, optimizer and
scheduler all match.

### 1. Learning rate differs by a factor of two

The EO condition trains at `8e-6`, the synthetic control at `4e-6`. The synthetic
control shares its learning rate with the SAR-only baseline rather than with the
condition it is meant to isolate.

This matters because the two conditions do not present the same optimization
problem. An ETF places its targets at the maximum possible mutual separation, so
the alignment term pulls features much further than real class means do - real
EO prototypes have high, non-uniform pairwise cosines, whereas the ETF has a
uniform cosine of exactly `-1/9` for ten classes. The gradient scale of the
alignment term therefore differs between conditions, and so does the learning
rate. Whether the observed gap reflects prototype content or a
prototype-specific interaction with step size cannot be separated from these
runs.

### 2. The seed sets barely overlap

The two conditions share exactly one seed, 42. Since each condition was run on a
different set of five seeds, per-seed pairing is impossible and only unpaired
comparisons are available.

This is a real loss of statistical power. A paired test removes seed-to-seed
variance, which in these experiments is substantial: the reported standard
deviations run from 1.3 to 2.0 accuracy points against effects of 1.5 to 4.0
points. Pairing on shared seeds would have made the same comparisons
considerably sharper at no extra compute cost.

### 3. Model selection uses the test set

All five training scripts select the reported checkpoint by evaluating
`evaluate_classifier` on `test_loader` each epoch and keeping the best macro-F1
(`src/train_eo_prototype_alignment.py` and its four siblings). There is no
validation split; `config.yaml` defines only `train_sar`, `train_eo` and
`test_sar`.

The paper describes this as "retaining the checkpoint with the highest validation
macro-F1", which suggests a held-out validation set was intended. As released,
the selection signal is the test set itself, so reported accuracies are optimistic
by an unknown margin. The effect is likely modest given only 25 epochs and a
balanced 770-image test set, and it applies to every method equally so the
*ranking* is probably unaffected - but the absolute numbers should be read as
best-epoch-on-test rather than clean held-out performance.

## What the statistics add

From `analysis/reported_stats.json`, generated by `src/run_reported_stats.py`:

- **EO prototype vs MMD alignment: not significant** (+1.5 pp, t = 1.63,
  p = 0.144). MMD discards EO labels entirely and only matches global feature
  distributions. The comparison that would establish transfer of *class-specific*
  optical structure is precisely the one that fails to reach significance.
- **That comparison had 37% power.** At five seeds it was more likely to miss an
  effect of the observed size than to find it, so its null result is weak
  evidence rather than evidence of absence. Fifteen seeds per arm would be needed
  for a conventional 80%.
- **Every comparison involving MMD is underpowered** (power 0.37 to 0.59). MMD is
  statistically indistinguishable both from the method above it and from the
  baseline below it, so its position in the ranking is unresolved.
- **The paper's own control comparison does hold** (+4.0 pp, t = 3.75, p = 0.007,
  96% power), subject to the confounds above.
- **Prototype geometry alone does not help**: the synthetic frame is
  indistinguishable from plain SAR-only fine-tuning (+0.5 pp, p = 0.661). This is
  a genuine and useful negative result - well-separated targets by themselves buy
  nothing.
- Conclusions are unchanged whether the published standard deviations are read as
  sample or population values, so nothing here depends on that ambiguity.

## A corrected design

To isolate prototype type as a single variable:

1. **Hold the learning rate fixed** across every prototype condition. If a
   learning rate must be tuned per condition, tune it on a validation split and
   report the sweep, so the comparison is between each condition at its own best
   setting rather than at two arbitrary points.
2. **Use one seed set for every condition**, and report paired per-seed
   differences alongside the unpaired test.
3. **Run at least 15 seeds per arm** if the EO-versus-MMD comparison is to be
   resolved. Fewer suffices for the larger effects: the EO-versus-synthetic gap
   needs only 3.
4. **Carve a validation split** from the training set for checkpoint selection,
   and touch the test set once.
5. **Extend the control beyond two points.** Real EO prototypes and an ETF differ
   in several geometric properties at once. `src/prototype_variants.py` builds the
   intermediate conditions - rotated, cosine-matched, label-permuted - that
   separate angular geometry from class identity from optical origin. In
   particular, a rotated copy of the real EO prototypes preserves every pairwise
   angle while destroying the correspondence to specific optical directions,
   which the ETF control cannot express.

## Scope of these remarks

These are observations about experimental design and statistical power, not about
correctness. The code is clear, the method is reasonable, and the released
implementation reproduces the described procedure. The reported effect may well
be real; the point is that the released experiments do not yet establish it, and
the additional runs needed to do so are inexpensive.
